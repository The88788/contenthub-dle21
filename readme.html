Модуль для DataLife Engine 21 Версия 1.1.1

ContentHub
Публикации пользователя и тегов

Отдельные страницы публикаций - по пользователю и по тегу - с группировкой по блокам: услуги одним блоком, кейсы другим, файлы третьим. Каждый блок со своими категориями, своим шаблоном и своим лимитом. Плюс страница /tags/ со списком всех тегов сайта.

Установка Сайт автора

Зачем это нужно

Штатная страница /user/{name}/news/ выводит публикации пользователя одним общим списком. Кейсы, услуги и файлы оказываются свалены вместе, без группировки и без разметки под каждый тип контента. На сайтах, где разные типы записей живут в разных категориях, это выглядит неприглядно.

Ровно та же проблема у штатной страницы тега /tags/{тег}/: все публикации тега идут одним списком в едином шаблоне краткой новости, хотя кейс, строка прайса и карточка файла - принципиально разные сущности.

ContentHub заменяет обе страницы на витрину: блок "Услуги" выводится таблицей прайса, "Кейсы" - сеткой карточек, "Файлы" - списком загрузок. Старый URL /user/{name}/news/ автоматически перенаправляется (301) на новую страницу. Плюс появляется страница /tags/ - облако всех тегов сайта. Блоки без публикаций не выводятся вовсе: ни заголовка, ни ссылки под блоком.

Область применения

  • Сайты-визитки фрилансеров и студий: публикации автора сгруппированы по смыслу, а не свалкой.
  • SEO-страницы тегов: посетитель по запросу "услуги DLE" сразу видит и кейсы, и прайс, и файлы по теме.
  • Каталоги и базы знаний: записи пользователя по разделам.
  • Порталы с несколькими авторами: страница автора как полноценное портфолио.
  • Любой DLE-сайт с разнотипным контентом в категориях.

Возможности

Гибкие блоки

Любое количество блоков, у каждого: заголовок, ID категорий, шаблон вывода, поле сортировки, направление, лимит постов, включение/выключение. Всё редактируется в админ-панели.

Шаблоны как угодно

Каждый блок собирается штатным тегом {custom}, поэтому блок может выглядеть как угодно: сетка карточек, таблица прайса, список файлов.

SEO-переезд

Старый URL /user/{name}/news/ отвечает 301-редиректом на страницу модуля. Позиции в поиске не теряются.

Страницы тегов

Модуль забирает на себя штатные URL /tags/{тег}/: публикации тега выводятся теми же блоками и шаблонами, что и у пользователя (фильтр tags= штатного {custom}). Адрес /tags/ показывает облако всех тегов сайта (шаблон taglist.tpl).

Пустые блоки не выводятся

Модуль считает посты каждого блока под текущую страницу (с учётом мультикатегорий). Нет публикаций - блок вырезается целиком: без "пустого" заголовка и ссылки под блоком.

SEO-заголовки из коробки

Страница тега получает заголовок вида Тег: кейсы, услуги и файлы и уникальные title/description - посадочная под коммерческие запросы, а не "публикации с тегом".

ЧПУ штатным механизмом

Человекопонятные URL работают через правила DLE 21 (engine/data/rules.json), без костылей в .htaccess.

SEO и карта сайта

Страницы тегов - полноценные посадочные: единый ЧПУ-URL, уникальные заголовки, вёрстка с блоками вместо сквозного списка. Генератор карты сайта DLE 21 штатно включает теги (tags_pages.xml в индексе sitemap.xml) - остаётся только повесить автозапуск:

# планировщик хостинга, раз в сутки
curl -s https://site.ru/cron.php?cronmode=sitemap

Подробная заметка об автогенерации sitemap с тегами - в комплекте и на сайте CMS DLE. Пустых тегов в DLE не бывает: в карту попадают только теги, привязанные к опубликованным постам.

Установка

Займет 5 минут. Требования: DLE 21.x, PHP 8.0+.

Загрузите файлы

Скопируйте содержимое папки upload/ в корень сайта, сохраняя структуру. Файлы contenthub.tpl и taglist.tpl положите в папку вашего шаблона (templates/ваш-шаблон/).

ФайлНазначение
engine/modules/contenthub.phpстраница модуля
engine/inc/contenthub.phpадмин-панель модуля
engine/data/contenthub.phpконфигурация
templates/.../contenthub.tplшаблон страницы пользователя/тега
templates/.../taglist.tplшаблон списка тегов /tags/
Подключите модуль в engine.php

В файле engine/engine.php найдите ветку switch ($do) и добавьте перед default::

case "contenthub":
    include (DLEPlugins::Check(ENGINE_DIR . '/modules/contenthub.php'));
    break;
(Опционально, можно пропустить) Пункт в меню админ-панели

Этот пункт можно пропустить целиком — настройки модуля всегда доступны по прямому адресу admin.php?mod=contenthub. Три варианта интеграции, от полного до минимального:

Полный: плитка в разделе "Настройки скрипта" на главной странице настроек (admin.php?mod=options&action=options) и пункт в левом меню админки (раздел "Настройки скрипта", внизу списка). Добавьте в engine/inc/options.php в массив $options['config']:

array(
    'name' => "Настройки Content Hub",
    'url' => "?mod=contenthub",
    'descr' => "Блоки публикаций пользователя и страниц тегов: категории, шаблоны вывода, сортировка и лимиты.",
    'image' => "admin_tagscloud.png",
    'access' => "admin"
),

и в engine/skins/default.skin.php в массив $options['config'] (в самый низ):

array(
    'name' => "Настройки Content Hub",
    'url' => "?mod=contenthub",
    'mod' => "contenthub",
    'access' => "admin"
),

Минимальный: только пункт в сайдбаре — добавьте второй фрагмент в любой массив $options[...] вашего skin-файла.

Без правок движка: открывайте настройки по прямому адресу admin.php?mod=contenthub.

Добавьте правило ЧПУ

В DLE 21 маршрутизацию выполняет встроенный роутер (FastRoute) по правилам из engine/data/rules.json. Правило обязательно: без него страница модуля отдаст 404. Правки в .htaccess для маршрутизации не помогут.

Откройте в админ-панели раздел "Управление ссылками ЧПУ" (admin.php?mod=friendlyurl), нажмите "Добавить новое правило" и заполните три поля:

Ключ:             contenthub
Ссылка ЧПУ:       /user/{user}/content/
Реальная ссылка:  /index.php?do=contenthub&user={user}

При сохранении через админ-панель кэш роутов сбрасывается автоматически. Если редактируете rules.json вручную, добавьте в начало массива и затем удалите файл engine/cache/system/route.rules.php:

"contenthub.user": ["/user/{user}/content/", "/index.php?do=contenthub&user={user}", "/user/{user}/content[/]"]
Подключите страницы тегов

Модуль обслуживает штатные URL тегов DLE. В файле engine/data/rules.json замените реальные ссылки у трёх существующих маршрутов (ключи и ЧПУ-ссылки не меняются):

"tags.page": ["/tags/{tag}/page/{cstart}/", "/index.php?do=contenthub&tag={tag}&cstart={cstart}", "/tags/{tag}/page/{cstart:\d+}[/]"],
"tags": ["/tags/{tag}/", "/index.php?do=contenthub&tag={tag}", "/tags/{tag}[/]"],
"tags.all": ["/tags/", "/index.php?do=contenthub", "/tags[/]"]

После правки удалите файл engine/cache/system/route.rules.php (кэш роутов). Пагинация /tags/{тег}/page/N/ остаётся на URL, но список выводится блоками с лимитами из настроек модуля.

(Опционально) Редирект со старой страницы

Чтобы /user/имя/news/ перенаправлял на модуль, добавьте в .htaccess перед строкой RewriteCond %{REQUEST_FILENAME} !-f:

RewriteRule ^user/([a-zA-Z0-9\_-]+)/news/$ /user/$1/content/ [R=301,L]
Откройте настройки модуля

В админ-панели перейдите в "Настройки скрипта" → "Настройки Content Hub" (либо откройте прямой адрес admin.php?mod=contenthub) и настройте контент-блоки: заголовки, ID категорий, шаблоны, сортировку, лимиты. Доступно только группе администраторов.

Готово: страницы открываются по адресам /user/ИМЯ/content/, /tags/ и /tags/ТЕГ/.

Настройка блоков

Настройки открываются по адресу admin.php?mod=contenthub (доступно группе администраторов). Для каждого блока задаются:

  • Заголовок - выводится над списком постов блока.
  • Категории (ID) - ID категорий через запятую, например 2,9,10.
  • Шаблон поста - имя tpl-файла из папки вашего шаблона без расширения, например cases, prices.
  • Сортировка и направление - как у штатного тега {custom}: по дате, рейтингу, просмотрам, комментариям, заголовку.
  • Лимит - максимум постов в блоке.

Шаблон страницы

Шаблон contenthub.tpl содержит секцию блоков [ch-blocks]...[/ch-blocks] и секцию каждого блока [ch-cases]...[/ch-cases], [ch-prices], [ch-files] (имена совпадают с ключами в конфигурации engine/data/contenthub.php). Выключенный в админке блок вырезается вместе с секцией. Внутри секции работают теги:

  • {ch-name} - имя пользователя (подставляется до парсинга {custom}, поэтому {custom author="{ch-name}"} работает штатно).
  • {ch-ключ-title} - заголовок блока.
  • {ch-ключ-cats}, {ch-ключ-tpl}, {ch-ключ-order}, {ch-ключ-sort}, {ch-ключ-limit} - параметры блока для {custom}.
  • {ch-error} - сообщение об ошибке (не найден, нет публикаций).

Для оформления используются классы .uc-block, .uc-block-title, .uc-empty - добавьте их в CSS вашего шаблона (минимальный набор есть в конце инструкции).

Минимальный CSS

.uc-block { margin: 0 0 48px; }
.uc-block-title { font-size: 26px; margin: 0 0 18px; }
.uc-empty {
    padding: 24px; border: 1px dashed #444; border-radius: 10px;
    color: #999;
}

Обновление до 1.1.1

Для установленной версии 1.1.0 достаточно обновить два PHP-файла. Настройки блоков, шаблоны сайта и правила ЧПУ сохраняются.

Сохраните резервную копию

Скопируйте текущие файлы модуля и конфигурацию engine/data/contenthub.php перед обновлением.

Замените файлы модуля и админки

Перенесите из upload/ файлы engine/modules/contenthub.php и engine/inc/contenthub.php с сохранением структуры.

Не перезаписывайте свою конфигурацию и шаблоны. Изменения базы данных и маршрутов для этого обновления не требуются.

Очистите кэш и проверьте страницы

Очистите кэш DLE. Откройте страницу автора, отдельного тега и облако /tags/. Если гостевой просмотр отключён, проверьте отказ доступа без авторизации.

Что изменилось

  • Запрет гостевого просмотра теперь охватывает все страницы модуля, включая облако тегов, и возвращает HTTP 403.
  • Неизвестный пользователь или тег получает настоящий HTTP 404. При включённом own_404 используется существующий 404.html.
  • Массивы вместо строковых параметров пользователя и тега отклоняются без предупреждений PHP.
  • Уточнены адреса установки и редиректа старой страницы публикаций.

Полная история версий — CHANGELOG.md. Подборки по-прежнему выводятся с лимитами, без пагинации.
