# ContentHub для DLE 21

Модуль "Публикации пользователя и тегов" для DataLife Engine 21: отдельные
страницы публикаций - по пользователю и по тегу - с группировкой по блокам.
Каждый блок - свои категории, свой шаблон вывода, свой лимит. Версия 1.1.0.

Живое демо: https://the88788.com/user/88788/

## Зачем

Штатная страница `/user/{name}/news/` выводит публикации пользователя
одним общим списком: кейсы, услуги и файлы свалены вместе и выглядят
"обрывком" сайта. То же самое делает штатная страница тега `/tags/{тег}/`:
все публикации тега идут одним списком в едином шаблоне краткой новости.
ContentHub заменяет обе страницы на страницу-витрину, где каждый тип
контента показан своим блоком со своей разметкой.

Подходит для:

- сайтов-визиток фрилансеров и студий (услуги отдельно, кейсы отдельно);
- каталогов и баз знаний (записи по разделам);
- порталов с несколькими авторами (страница автора как портфолио);
- SEO-страниц тегов, где посетитель должен сразу увидеть и кейсы, и
  прайс, и файлы по теме;
- любого DLE-сайта, где разнотипный контент разложен по категориям.

## Возможности

- Страница `/user/{name}/content/` с блоками публикаций пользователя.
- Страница `/tags/{тег}/` с блоками публикаций с тегом - теми же блоками,
  с теми же шаблонами и сортировкой (фильтр `tags=` штатного `{custom}`).
- Страница `/tags/` - облако всех тегов сайта (шаблон `taglist.tpl`,
  ссылки-чипы без счётчиков).
- Блоки настраиваются из админ-панели DLE (`?mod=contenthub`):
  для каждого блока - заголовок, ID категорий, шаблон, сортировка, лимит,
  включение/выключение. Одна настройка обслуживает и страницу пользователя,
  и страницу тега. Блок без публикаций не выводится вовсе: ни заголовка,
  ни ссылки под блоком.
- Шаблонный вывод каждого блока через штатный тег `{custom}`: блок может
  выглядеть как угодно (сетка карточек, таблица прайса, список файлов).
- Редирект 301 со старого URL `/user/{name}/news/` на страницу модуля.
- Доступ для гостей включается/выключается в настройках.
- ЧПУ через штатный механизм правил DLE 21 (`engine/data/rules.json`).

## Требования

- DataLife Engine 21.x
- PHP 8.0+

## Установка

1. Скопируйте файлы из `upload/` в корень сайта, сохраняя структуру.
   Шаблоны `contenthub.tpl` и `taglist.tpl` положите в папку своего
   шаблона.
2. В `engine/engine.php` добавьте в switch перед `default:`:

   ```php
   case "contenthub":
       include (DLEPlugins::Check(ENGINE_DIR . '/modules/contenthub.php'));
       break;
   ```

3. (Опционально, можно пропустить) Пункт в меню админ-панели. Этот пункт
   можно пропустить целиком — настройки модуля всегда доступны по прямому
   адресу `admin.php?mod=contenthub`. Есть три варианта интеграции, от
   полного до минимального:

   **Полный: плитка в "Настройки скрипта" + пункт в сайдбаре.** Чтобы
   настройки открывались с главной страницы настроек
   (`admin.php?mod=options&action=options`) и из левого меню админки
   (раздел "Настройки скрипта", самый низ списка), добавьте в
   `engine/inc/options.php` в массив `$options['config']`:

   ```php
   array(
       'name' => "Настройки Content Hub",
       'url' => "?mod=contenthub",
       'descr' => "Блоки публикаций пользователя и страниц тегов: категории, шаблоны вывода, сортировка и лимиты.",
       'image' => "admin_tagscloud.png",
       'access' => "admin"
   ),
   ```

   и в `engine/skins/default.skin.php` в массив `$options['config']`:

   ```php
   array(
       'name' => "Настройки Content Hub",
       'url' => "?mod=contenthub",
       'mod' => "contenthub",
       'access' => "admin"
   ),
   ```

   **Минимальный: только пункт в сайдбаре.** Добавьте только второй фрагмент
   (в `engine/skins/default.skin.php`) - в любой массив `$options[...]`,
   например в конец `$options['config']`.

   **Без правок движка:** настройки открывайте по прямому адресу
   `admin.php?mod=contenthub` (добавьте ссылку в закладки браузера).

4. Добавьте правило ЧПУ страницы пользователя. В DLE 21 маршрутизацию
   выполняет встроенный роутер (FastRoute) по правилам из
   `engine/data/rules.json`; без правила страница модуля отдаст 404, правки
   в .htaccess не помогут. Откройте в админ-панели раздел "Управление
   ссылками ЧПУ" (`admin.php?mod=friendlyurl`), нажмите "Добавить новое
   правило" и заполните три поля:

   ```
   Ключ:             contenthub
   Ссылка ЧПУ:       /user/{user}/content/
   Реальная ссылка:  /index.php?do=contenthub&user={user}
   ```

   Либо вручную добавьте в начало `engine/data/rules.json`:

   ```json
   "contenthub.user": ["/user/{user}/content/", "/index.php?do=contenthub&user={user}", "/user/{user}/content[/]"]
   ```

5. Подключите страницы тегов (обновление с 1.0.x и новая установка). Модуль
   забирает на себя штатные URL тегов: в `engine/data/rules.json` замените
   реальные ссылки у трёх существующих маршрутов `tags`, `tags.page` и
   `tags.all` (ЧПУ-ссылки и ключи не меняются):

   ```json
   "tags.page": ["/tags/{tag}/page/{cstart}/", "/index.php?do=contenthub&tag={tag}&cstart={cstart}", "/tags/{tag}/page/{cstart:\d+}[/]"],
   "tags": ["/tags/{tag}/", "/index.php?do=contenthub&tag={tag}", "/tags/{tag}[/]"],
   "tags.all": ["/tags/", "/index.php?do=contenthub", "/tags[/]"]
   ```

   После правки удалите кэш роутов: файл
   `engine/cache/system/route.rules.php`. Пагинация страницы тега
   (`/tags/{тег}/page/N/`) остаётся на URL, но модуль выводит список блоками
   с лимитами из настроек, листание по страницам не выполняется.

6. (Опционально) Для редиректа со старой страницы добавьте в `.htaccess`
   перед правилом `RewriteCond %{REQUEST_FILENAME} !-f`:

   ```
   RewriteRule ^user/([a-zA-Z0-9\_-]+)/news/$ /user/$1/content/ [R=301,L]
   ```

7. Откройте в админ-панели "Настройки скрипта" → "Настройки Content Hub"
   (или прямой адрес `admin.php?mod=contenthub`) и настройте блоки. Страницы
   модуля доступны по адресам `/user/ИМЯ/content/`, `/tags/` и `/tags/ТЕГ/`.

Подробная инструкция: `readme.html`.

## Шаблоны

`contenthub.tpl` содержит две ветки: `[ch-user]…[/ch-user]` (блоки с
фильтром `author=`) и `[ch-tag]…[/ch-tag]` (те же блоки с фильтром `tags=`).
Модуль оставляет ветку активного режима, вторую вырезает целиком, поэтому
разметка неактивной ветки на странице не появляется. Ссылки под блоками
(например, "Все кейсы") - обычные `<a>`, их адреса правьте под свой сайт.

`taglist.tpl` - страница `/tags/`: модуль подставляет в `{tags}` ссылки-чипы
всех тегов сайта (равномерные, без счётчиков, в алфавитном порядке).
